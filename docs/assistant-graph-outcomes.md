# Media Assistant Graph outcomes

Graph review derives its primary outcome and action from recorded operations and validation. Rename names the proposed title and uses **Rename workflow**; additions use **Add to canvas**; node edits use **Apply node changes**; layout uses **Tidy workflow**; mixed changes use **Apply changes** and name each effect. Applying remains separate from running.

Authored creative context remains in normal replies, operation details and an explicit **Assistant context** disclosure. Arbitrary summary prose cannot override the primary outcome or terminal fallback. Shared guidance covers replies, tool summaries, review, progress, recovery and completion. No keyword blacklist or extra model call is added.

Completion requires successful browser delivery. Saved confirmations alone cannot prove current content or layout. Failed application offers **Review graph again**. Missing-media copy names all required inputs and counts distinct inputs; other validation errors remain visible. Fresh reviews establish updated readiness after media selection.

Existing persistence, approval tokens, validation, pricing and run contracts are preserved. Layout proposals remain separate from content changes under the existing contract.

Verification uses rendered Graph review, typed terminal fallback and the actual in-app Graph Studio browser. Run pure web tests with `npm --workspace apps/web test`. Follow repository runtime boundaries before runtime checks; backend pytest's database fixtures require separate authorization. Local acceptance does not establish remote CI, release readiness or paid output quality.
